## 4. 易错点 / 错题本

| # | 错题 | 你的复述 | 错在哪 | 二次错了吗 |

| 1 | 块 2 段 2:调用链路方向 | "level → init → app_main" | 方向反了,应该是 app_main → init → level | ❌ |

| 4 | 块 1 抽问:`SRCS` 报错 | "外面 CMake 和组件 CMake 没对齐" | **死活**!实际是`SRCS` vs **实际文件名**对不上;**根 vs main 的 CMake**互不要求一致(已补) | ❌ |
| 4b | 块 1 第二轮:对齐概念 | "两个文件不知道编译哪个 / 名字和根 CMake 对齐" | 第一轮我判严了,**你第二轮讲对了**:SRCS 找源文件、project 配工程名、文件名错就找不到源文件。**满分通过** | ✅ |
| 4c | 块 2 第二轮:组件复用 | "需要重写,芯片/flash/size 每个新电脑都要走" | **严重错**!组件 = 整个文件夹,原样复制即可;**芯片配置归 sdkconfig,跟组件无关**(已补) | ❌ |
| 4e | 块 3 第二轮:Q1 没 CMake | "找不到源文件" | **错**!实际是**静默跳过** — 不报错也不编译;main include 时才爆 fatal。**沉默的杀手**(已补) | ❌ |
| 4f | 块 4 第二轮:Q2 幽灵 bug | "不知道为啥可能编过" | **对的** — 这就是"幽灵 bug"。**没 REQUIRES = 借别人饭,别人一撤你就饿死**;REQUIRES 是自种粮(已补) | ❌ |
| 4g | 块 6 第二轮:1ULL 浪费 | "24 位写不到 / 浪费" | 方向对但含糊。**ULL 不是修现在的 bug,是防未来 50+ GPIO 的 bug**;`int` 32 位装不下 50 时 = 未定义行为(已补) | ❌ |

## 5. 老师抽问题库(常备)

| 老师爱问 | 你必须答出 |
|---|---|
| "为什么是 `1ULL << pin` 而不是 `1 << pin`?" | GPIO_NUM 最大 45+,`int` 32 位会溢出,`ULL` 强制 64 位 |
| "把 RGB 接到高电平点亮,代码哪里要改?" | `rgb_set_color` 里 `? 0 : 1` 改成 `? 1 : 0`;颜色宏 1/0 含义取反 |
| "忘了写 `REQUIRES esp_driver_gpio` 会怎样?" | `driver/gpio.h` 找不到,main 包含 `rgb_set.h` 时报 `fatal: driver/gpio.h: No such file` |
| "main 里 `#include "rgb_set.h"` 就能找到,include 路径在哪设的?" | `rgb_set` 组件的 `CMakeLists.txt` 里 `INCLUDE_DIRS "include"`,IDF 自动加到全局 |
| "`RGB_COLOR_YELLOW` 的值是多少?为什么?" | `0x04 \| 0x02 = 0x06`,红+绿=黄 |
| "为什么要在 `while(1)` 里循环?删了会怎样?" | 删了只显示一种颜色后退出,`app_main` 返回 = 任务死亡 |
| "把 `vTaskDelay` 删了会怎样?" | CPU 100% 占用,其他任务饿死,看门狗重启 |
| "`gpio_config_t` 为什么一次性写完?" | 位掩码批量配置,一次函数调用搞三个引脚 |
| "`components/` 改个名字能编译过吗?" | 不能,`main/CMakeLists.txt` 里 `REQUIRES rgb_set` 名字对不上就找不到 |
| "main 里没写 `REQUIRES rgb_set` 会过吗?" | 能编过(头文件已被全局包含),但不规范,留隐患 |
| "为什么是 `pdMS_TO_TICKS(1000)` 而不是直接 `vTaskDelay(1000)`?" | RTOS 不认秒,只认滴答;不同 `configTICK_RATE_HZ` 配置下"1000"含义不同,宏永远换算成"1 秒" |
| "为什么 ESP_LOGI 比 printf 好?" | 自带时间戳(开机后 ms 数)和标签(模块名),多任务调试能定位"谁、什么时候" |
| "低电平点亮板子怎么改代码?" | `? 0 : 1` 改成 `? 1 : 0`;颜色宏 1=亮 的语义不变 |
| "为什么默认低电平点亮?" | LED 接 VCC → LED → GPIO,**GPIO 灌电流能力 40mA 比拉电流 20mA 强,所以低电平驱动更亮** |
